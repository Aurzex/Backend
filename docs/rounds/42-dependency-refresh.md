# 第四十二轮记录 — 依赖刷新(取最高稳定版)

## 0. 一句话
按"不考虑兼容"的授权把 `Cargo.toml` 的直接依赖与 `Cargo.lock` 的解析结果刷新到 crates.io 当前最高稳定版;刷新后格式门、Clippy 门与全量测试(含真机用例)全部通过。

## 1. 任务背景
2026-10-02 提出依赖升级要求,授权口径为"不考虑兼容"。此前依赖版本由历轮零星引入后未再统一刷新;仓库的既有约束(同步阻塞、单 `rlib` crate、零 async、不引入新第三方依赖)不变。

刷新口径为**最高稳定版**(`max_stable_version`),预发布版不在候选内;"不考虑兼容"指不为旧版行为保留垫片、可直接取语义化主版本跃迁的候选——核对结果表明该授权实际未被触发,详见 §2 与 §6。

## 3. 实际变更

`Cargo.toml` 仅改两处版本号(`thiserror` 改为 `2.0.21`、`ureq` 改为 `3.4.2`),特性列表与其余段(edition、`crate-type`、`profile`、`[lints.rust]` 等)均未动。

`Cargo.lock` 由 `cargo update` 重解,选取口径为 "highest Rust 1.99.0 compatible versions",共 19 个包变动。

## 4. 未变更项
- 源码、测试与 CI 均无改动:`src/`、`tests/`、`.github/` 三个目录的差异为空。
- 仓库无 `rust-toolchain.toml`,CI 三个 job 使用 `dtolnay/rust-toolchain@stable`,未钉死版本,故依赖刷新不存在需要同步的工具链文件。
- 本机工具链为 cargo 与 rustc 1.99.0(2026-08-27 / 2026-09-28 构建),`cargo update` 的兼容上限即以此为界。

## 5. 验证

| 命令 | 结果 |
| --- | --- |
| `cargo fmt --check` | 通过 |
| `cargo clippy --all-targets -- -D warnings` | 通过,零告警 |
| `cargo test` | 通过,退出码 0;14 个测试目标共 142 项通过、0 项失败、12 项按既有标记忽略 |

真机用例(依赖本机凭据与线上服务)在依赖升级后实际运行:`live_features` 三项、`convert_live` 两项、`compile_live` 一项通过;未跑的忽略项(`convert_live` 三项、`compile_live` 一项,以及语料/性能类目标)沿用既有 `#[ignore]` 标记。该结果覆盖了 `ureq` 3.4.2 的 HTTP 链路、`rustls` 0.23.45 的 TLS 握手与 `tungstenite` 0.30.0 的 WebSocket 链路,即依赖升级所触及的全部运行时依赖。

## 6. 影响面与风险
- 两个直接依赖的变更均落在语义化兼容范围内,不存在需要处理的破坏性 API 变更;因此"不考虑兼容"的授权没有实际触发的对象(直接依赖中无更高主版本的候选)。
- 未经编译验证的传递依赖变更集中在构建脚本与传输/压缩/哈希链路上,由 §5 的编译与真机用例覆盖。
- 真机用例依赖网络与有效账号,其结果仅代表 2026-10-02 当日线上服务的可用状态。

## 7. 遗留
无待做项。后续同口径刷新的步骤为:逐项查 crates.io 的 `max_stable_version` 与 `Cargo.toml` 比对,改落后项,再执行 `cargo update`,最后跑 §5 三道门。
