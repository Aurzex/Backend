# 第三十六轮记录 — 凡是往 Kitten4 写名字的地方,均须通过"编辑器词汇"判据

## 1. 缘起

rounds/35 修复 `theatre.groups` 后,角色能够显示;本轮继续收敛**"编辑器不认识即剔块/清影子"**这一保真缺口
(rounds/34 §4nonies 的刻意取舍)。先量化,再定点修复。

## 2. 发现一:块路径的**单候选分支**缺少词汇判据

`reverse_kind` 的歧义分支(`Some(candidates)`)是按"编辑器认识的优先"挑选的,
但**单候选分支**(`Some([only])`)**直接取那一个候选** —— 而表里的 Kitten 侧名字是 **Kitten3 口径**。

实测(词汇表 349 条 + 平台语料计数,判据是"平台上真实作品用什么"):

| 名字 | 编辑器注册表 | 平台 40 件 Kitten4 语料出现次数 |
| --- | --- | --- |
| `text` |  认识 | **1338** |
| `get_split_options` |  不认识 | **0** |

因此 KN `text`(KN 语料 11 件里 463 次)被映射成 `get_split_options`,写出阶段按"编辑器不认识"将其**剔除**。
在两件真作品的报告中,`get_split_options` 占被剔块的主要部分(98 + 116 块)。

## 3. 发现二:影子路径为**同一缺陷**

影子 XML 的类型由 `untransform_shadow_xml` 反演,它同样"只取单候选、不看词汇表",因此
KN `text` 的影子被写成 `get_split_options`,进而被**清空**(170 + 178 条)。
**块与影子必须共用同一套取名规则** —— 本条为本轮最主要的结论。

## 4. 修法

新增 `pick_single_reverse_name(kn_kind, candidate)`(块与影子共用):

1. 候选编辑器认识则用它;
2. 否则 KN 名编辑器认识则**保留 KN 名**(名字与形状均不需改动,正向解析最稳);
3. 否则照旧给出候选,由写出阶段剔除/清空并逐类报告(不在此处静默改名)。

块路径:`Some([only]) => pick_single_reverse_name(...)`;影子路径:单候选同样经过该函数
(多候选即歧义时影子保持原名:形状的挑选属于块侧)。

| `now`(273988379) | 415 -> **286** | 224 -> **46** |
